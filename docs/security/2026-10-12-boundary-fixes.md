# CloudSSH 安全报告核验与修复

核验日期：2026-10-12。代码基线：`88f55f4ff1cf20dd06ee1ab3d56c50509f4a3c9b`，修复发布版本：`2.6.0-cloudssh.56`。本记录形成时描述的是本地修复与隔离测试；发布状态以 GitHub Release 和线上运行时核验为准。

## 核验结论

| 报告                      | 结论                                                                                                                                                              | 修复                                                                                                                              |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 1：文件传输本地任意写     | 危险分支真实存在。目标地址被识别为本机时，源 SFTP 的 `fastGet` 绕过目标 SFTP，写入应用进程所在文件系统。实际影响受进程权限和容器挂载限制，未证明宿主机 root RCE。 | 删除本机地址判断与本地落盘捷径，普通文件、归档中转和逐项传输统一写入目标 SFTP。                                                   |
| 1：任意目标 SSH 连接      | 已认证用户快速连接任意 SSH 地址是现有产品功能，可用于 TCP/SSH 握手探测。不能据此直接认定未授权 SSRF、HTTP 元数据读取或任意协议请求。                              | 校验连接参数类型、端口整数范围及会话上下文；不新增破坏正常内网运维的私网封禁。                                                    |
| 2：未授权使用他人跳板凭据 | 真实。跳板解析缺少请求用户授权检查，并存在共享快照失败后读取所有者凭据的回退。未证明向攻击者直接返回明文。                                                        | 统一使用 `resolveHostById`，先检查连接权限再解密。主机创建、更新时校验每一跳，连接时重新校验；修正 metrics、tmux 使用请求人身份。 |
| 3、4：Vault callback XSS  | 同一个真实问题。动态错误正文未转义，标题在实际调用中为固定文本；报告的标题双重反射描述不准确。                                                                    | 所有动态 HTML 文本统一转义，拒绝重复及对象查询参数，覆盖尾斜杠入口与认证服务返回的错误。                                          |
| 5：全屏入口失败放行       | 真实，但只证明未登录用户能看到应用外壳，后端 API 仍要求认证。                                                                                                     | 401/403 显示登录；网络、429、5xx 显示重试并保留登录状态；验证成功才挂载应用。                                                     |
| 6：LDAP 参数类型缺失      | 真实的健壮性缺陷。仓库使用 SQL/Drizzle，并非 MongoDB；未证明注入或认证绕过。                                                                                      | 查询或 LDAP 连接前验证正整数供应商 ID、字符串用户名和密码、可选布尔记住登录字段，错误输入返回 400。                               |

另将文件管理会话所有权判断改为缺失即拒绝。普通连接、TOTP、Warpgate 与专用传输会话均设置请求用户身份。

已保存主机的地址、端口和凭据由服务端授权解析覆盖，不能用自己的任意已保存主机 ID 配合伪造 IP 改变连接目标。专用传输连接也再次解析主机权限，因此报告中“传输完全没有二次主机授权”的描述不成立。

官方 [GHSA-773j-p4cp-q79p](https://github.com/Termix-SSH/Termix/security/advisories/GHSA-773j-p4cp-q79p) 已通过 GitHub 仓库公告 API 核实：严重性为高，影响 `< 2.7.0`，官方修复版本为 `>= 2.7.0`。本次对 fork 做针对性修复，不声称完成上游全版本升级。

## 验证

- 隔离回归在修复前重现本地写分支、未授权跳板、XSS 与入口失败放行。文件写测试只记录模拟 `fastGet` 调用，没有真实敏感文件写入；跳板测试没有真实登录第三方主机。
- 全量 Vitest 分批覆盖 274 个文件：2259 项通过，3 项跳过，0 项最终失败。每个测试子进程设置 60 秒硬超时。
- 首次运行有一项本地控制面测试 `fetch failed`；该文件 14 项单独重跑通过，原批次 178 项完整重跑通过。保留该首次失败事实，不将其描述为首次全绿。
- 独立代理只读复审未发现阻断，另外复跑其他修复组的 5 个文件、80 项测试通过。
- `npm run build` 通过，包含 Vite 构建与后端 TypeScript 编译。全仓 Prettier 通过，ESLint 0 错误、42 个既有警告。
- 单独前端 `tsc -p tsconfig.app.json --noEmit` 未通过：修改前后基线均为相同的 338 条错误，逐条比较没有新增或删除。本轮没有修复仓库既有类型债务。

安全修复位于分支 `fix/security-boundaries-20261012`，原始工作区中的性能改动保留。
