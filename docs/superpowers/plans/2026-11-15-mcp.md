# CloudSSH MCP Implementation Plan

**Goal:** Deliver HTTP MCP and four management tabs using existing Agent services.
**Architecture:** Official SDK transport at /agent/mcp, authenticated per request; shared service instances, existing hashed tokens, dedicated metadata-only invocation ledger. UI reachable from Agent integration.
**Tech Stack:** TypeScript, Express 5, React 19, SQLite, MCP SDK, Zod, Vitest.
**Spec:** docs/plans/2026-11-15-mcp-design.md

## Global constraints

- Node >=22.12.0; preserve unrelated working changes; no commits.
- Credentials never appear in context or audit responses. Enforce current project grants and operation scopes.

## Review focus

- Expired/revoked keys must fail subsequent requests.
- Out-of-project resources must be denied by existing services.
- Invalid arguments and duplicate request IDs must not dispatch duplicate writes.
- History must not leak another administrator's projects or command text.
- Configuration must use the actual server origin, including remote desktop mode.

## Tasks

- [x] Backend tools and transport: 18 tools, official SDK negotiation, scope filtering, strict schemas and metadata audit. Existing job/file services retain retry semantics.
- [x] Management and runtime: hashed keys, current-project authorization, owner/admin isolation, recent MFA, paginated 30-day history and shared service wiring.
- [x] UI: four-tab management dialog reachable from Agent integration; configuration, schemas, key lifecycle and history filters.
- [x] Verification: targeted tests, production frontend build, backend types, focused lint and diff checks completed. Full frontend type check remains blocked by 334 unrelated diagnostics; no MCP-related diagnostics.
