# CloudSSH 已批准安全升级实施计划

本轮将三个已批准设计一次性落地：用 Ed25519 设备身份替换长期 Agent Token，隔离管理员
日常项目列表中的其他用户个人空间，并在文件夹行增加快捷新增主机。版本目标为
`2.6.0-cloudssh.12`；本计划只完成代码、测试、文档与 GitHub 推送，不直接部署生产。

## 范围

- 包含：数据库迁移、设备注册与签名鉴权、设备审批管理、Skill 本机密钥与签名、旧 Token
  撤销、个人空间普通/管理员接口隔离、管理员个人空间界面、文件夹快捷新增、测试和文档。
- 不包含：生产部署、MCP、本地桥接、长期 Token 兼容登录、内网 Connector、逐命令审批。

## 实施步骤

1. 在数据库模型和幂等迁移中新增设备、设备项目、设备码与 nonce 表，给审计事件增加设备
   身份引用；迁移时撤销全部旧 Token，但保留历史行。
2. 将 Agent principal 从 Token 身份改为设备身份，复用现有项目解析、服务器目录、scope、
   会话和 Job 并发限制；清除对可见服务账号的依赖，只保留内部外键兼容身份。
3. 新建设备码注册/轮询公开端点和登录用户的审批、列表、重命名、撤销端点；设备码只存
   摘要，设置短有效期、单次消费和频率限制。
4. 在原始请求正文校验前建立 Ed25519 签名中间件，规范化方法、路径、查询、时间戳、nonce
   和正文哈希，并实现时间窗口与 nonce 防重放。
5. 重写 `AgentIntegrationPanel` 和管理 API，只展示待审批设备、已批准设备及其项目、scope、
   并发和有效期，不保留创建 Token、MCP或本地桥接入口。
6. 重写 `cloudssh-agent` Skill 的 `auth login/status/logout`：首次生成 Ed25519 密钥，写入系统
   安全存储，显示设备码与指纹并轮询审批；所有 Agent 请求自动签名，不读取或保存 Token。
7. 将普通项目仓库和路由改为永远隐藏其他用户个人空间，并增加仅实例管理员可调用的用户
   个人空间摘要、主机查看、连接、编辑、解除关联/删除接口及审计。
8. 在用户管理中增加个人空间入口和明确的代管提示，复用现有主机编辑与连接能力；不得把
   目标个人空间写入普通项目切换状态。
9. 给 `FolderItem` 增加权限受控的 `+`，把当前项目 ID 和规范化文件夹路径传给现有
   `HostManager`；保存后刷新并展开目标文件夹，取消后清除预填。
10. 更新中英文文案、CloudSSH 文档、README、Skill 指南和版本号，删除 Token、服务账号、
    MCP、本地桥接及服务器白名单的残余用户文案。
11. 分组运行设备认证、项目权限、管理员个人空间、主机树和 Skill 跨进程测试，每次命令
    最长 60 秒；补充篡改签名、重放、过期/撤销、旧 Token 拒绝、多项目解除关联和跨项目
    文件夹伪造等安全回归。
12. 运行完整单元测试、类型检查、Lint、格式检查、正式构建和敏感信息扫描；代码审查通过
    后提交并推送 GitHub。生产部署另行确认并执行新备份、SHA-256 校验和隔离恢复验证。

## 风险控制

- 原始正文签名校验必须早于 JSON 业务解析，避免重序列化歧义。
- 设备撤销应立即拒绝新请求和租约续期；已有远端 tmux 不自动销毁，仍由显式关闭控制。
- Linux/macOS 安全存储路径需保留平台检测并在不可用时失败关闭，不得降级为明文文件。
- 管理员删除多项目关联主机默认只解除个人空间关联，事务内二次检查防止并发误删。
- 数据库迁移必须幂等，旧 Token 不得因回滚或重复启动重新激活。
